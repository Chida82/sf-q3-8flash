## 2. Feasibility (design D4; no GPU; only if 1.5 passes)

- [x] 2.1 Rollback: what verifying up to 8 rows needs for GDN and the KV caches, against the current 3-row path. *(2026-11-20, read from the code, no run. The verify is exact per row today (`verify_rows_exact`: each row computes as a single decoded token, so greedy `--mtp` output is byte-identical to plain) and is capped at 3 rows in a few places: two named snapshots (`snap_*` after row 0, `snap2_*` after row 1) passed as two (buffer, row) pairs to the GDN front, GDN scan and PLE convolution wrappers; `qwen4_graph_fused` (T <= 2, or 3 in a verify); the folded Q2_K down (T <= 3); `qwen4_verify_attention_rows` (`rows[3]`). KV and indexer rows past the kept position are overwritten, as today. One recurrent snapshot is 36 layers x 48 x 128 x 128 f32, about 108 MiB, plus the convolution and PLE histories (small). Upstream commit `7e6ab2f` (not in `upstream/main`; `187` took only its lookup index) already extends this verify to 16 rows: n consecutive snapshot slots per layer (`ds4_gpu_qwen4_set_snapshot_rows`), five kernels changed, `tests/test_qwen4_verify_exact.c`, 755 insertions over nine files, and `a4d4804` builds on it. Its cost to measure: a block of 8 rows writes 7 snapshots, about 760 MiB of state per cycle; Splash avoids that by taping each row's GDN inputs and folding the accepted path into the state at the next step, which is the fallback if the snapshot traffic shows in the cycle time.
